# 국내 데이터 출처 전환 설계 (설계만, 아직 코드 없음)

지금 1차 버전은 키 없이 쓰는 해외 무료 출처를 쓴다. 정식 출시 전에 아래처럼 국내 공식 출처로 바꾼다.

## 지금과 바꿀 곳

| 정보 | 지금 | 바꿀 곳 | 이유 |
|---|---|---|---|
| 물때·만조/간조 시각 | 월령으로 폰에서 계산(7물때식) | 국립해양조사원 바다누리 조석예보(고조·저조 시각과 조위) | 계산값은 지역별 차이를 반영 못 함. 실제 만조·간조 시각이 필요 |
| 수온 | Open-Meteo 해양 예보(격자) | 바다누리 실시간 관측(조위관측소·해양관측부이 수온), 없으면 Open-Meteo | 관측값이 낚시인 체감과 맞음 |
| 날씨·바람 | Open-Meteo | 기상청 단기예보(공공데이터포털, 5km 격자) | 국내 예보 정확도, 공식 출처 표기 |
| 파고·풍랑 | Open-Meteo 해양 | 기상청 해상예보 + 특보(풍랑주의보) | 출조 가능 여부 판단에 특보가 핵심 |
| 주변 화장실·식당·영업시간 | OSM Overpass + 카카오맵 링크 | 카카오맵·네이버지도 주변 검색 딥링크(1차 버전에 버튼 추가함), 이후 카카오 로컬 API | 국내 영업시간·폐업 정보는 카카오/네이버가 정확 |

## 구조

- 앱이 각 API를 직접 부르지 않고 작은 서버(예: Cloudflare Workers 또는 Supabase Edge Function) 하나를 거친다.
  - API 키를 앱에 넣지 않기 위해서.
  - 바다누리·기상청 응답을 포인트 근처 관측소/격자로 바꾸고 10~30분 캐시해 호출량을 줄이기 위해서.
- 앱 쪽은 `src/lib/marine.ts`의 `fetchMarine()` 반환 모양(MarineNow)을 그대로 두고 내부만 바꾼다. 화면 코드는 손대지 않는다.
- 서버가 안 되면 지금처럼 Open-Meteo, 그것도 안 되면 폰 계산 물때로 내려간다(통신 약한 곳 대응 유지).

## 필요한 것

1. 공공데이터포털 회원가입 후 활용 신청: 기상청 단기예보 조회서비스, 기상청 특보 조회, 국립해양조사원 조석예보·실시간 관측(바다누리 OpenAPI).
2. 카카오 디벨로퍼스 앱 등록(로컬 API 키). 네이버는 딥링크만 쓰면 키 불필요.
3. 서버 호스팅 1곳(무료 범위로 시작 가능).

## 순서

1. 바다누리 조석예보: 만조·간조 시각을 물때 차트와 포인트 화면에 표시 (가장 효과 큼)
2. 기상청 특보: 풍랑주의보 시 출조 지수 경고
3. 기상청 단기예보로 날씨 교체
4. 카카오 로컬 API로 편의시설 목록 교체(영업시간 포함)
